State & Derived

State is the reactive heart of a Lyap scope. Declare it once, read and write it from anywhere in the container, and every bound element stays in sync automatically.

Declaring state

Call state({...}) inside a <script type="lyap"> block. Every property you declare is immediately available to directives, derived values and functions in the same container.

<div>
    <script type="lyap">
        state({
            count: 0,
            firstName: 'Alex',
            lastName: 'Smith'
        });
    </script>

    <p>Hello, <span ly-text="firstName"></span>!</p>
    <p>Count: <span ly-text="count"></span></p>
</div>

Derived values

Derived values are read-only properties computed from state. They are lazy, memoized and only re-run when the specific state they read changes.

<div>
    <script type="lyap">
        state({
            firstName: 'Alex',
            lastName: 'Smith'
        });

        derived({
            fullName() {
                return `${firstName} ${lastName}`;
            }
        });
    </script>

    <p>User: <span ly-text="fullName"></span></p>
</div>

Never assign to a derived value. Derived properties are read-only. Change the state they depend on instead.

Functions

Functions declared at the top level of a <script type="lyap"> block become callable actions. They have direct access to state, derived values and other functions in the same scope.

<div>
    <script type="lyap">
        state({ count: 0 });

        function increment() {
            count++;
        }

        function reset() {
            count = 0;
        }
    </script>

    <p>Count: <span ly-text="count"></span></p>
    <button ly-on:click="increment">Increment</button>
    <button ly-on:click="reset">Reset</button>
</div>

You can also inline a micro-expression directly in a directive using the : prefix — see Events & Actions.

Expressions

Directives evaluate safe, sandboxed expressions — there is no eval() or new Function() in Lyap. Property access, arithmetic, comparisons, string concatenation, object and array literals are all supported.

<p ly-text="count * 2"></p>
<p ly-text="fullName.toUpperCase()"></p>
<p ly-text="price > 100 ? 'expensive' : 'cheap'"></p>
<p ly-text="user.avatarUrl"></p>
<button ly-attr:disabled="isSaving || !isValid">Save</button>

Multiple scripts, one scope

A container may hold several <script type="lyap"> blocks — they all share the same scope context. This is handy for keeping separate concerns tidy.

<div>
    <script type="lyap">
        state({ count: 0 });
    </script>

    <script type="lyap">
        function reset() {
            count = 0;
        }
    </script>

    <p ly-text="count"></p>
    <button ly-on:click="reset">Reset</button>
</div>

Key collisions. If two scripts in the same container declare the same state key, Lyap logs a guard warning: [Lyap Guard Warning] State key collision: "count" already declared in container scope.
