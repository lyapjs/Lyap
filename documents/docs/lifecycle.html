Lifecycle & Scopes

Every Lyap container owns a scope. Hooks let you run code at precise moments in that scope's life, and scopes inherit from their parent containers.

The lyap script block

A <script type="lyap"> block binds to its nearest parent container element. Browsers ignore the block during parsing, so nothing runs until Lyap boots.

<div>
    <script type="lyap">
        state({ count: 0 });

        init(() => {
            console.log('Scope initialized');
        });

        mount(() => {
            console.log('Mounted container');
        });

        destroy(() => {
            console.log('Scope destroyed');
        });
    </script>
    <p ly-text="count"></p>
</div>

init — before first render

init(() => {...}) runs during scope creation, before the element is attached to the active DOM. Use it for one-time setup that doesn't need the DOM.

mount — attached to the DOM

mount(() => {...}) runs immediately after the element and scope are attached to the DOM tree. This is the right place to wire up timers, observers or external listeners that need a live element.

The mount() hook starts the timer and paints the clock directly; the Pause / Resume button is reactive — it toggles the running state, which the timer reads on each tick. While paused the clock freezes and resumes where it left off, because the paused interval never advances the secs counter. Notice the cleanup() call inside mount(): it registers a teardown for resources created during that mount cycle, so the timer is cleared when the scope is destroyed.

<script type="lyap">
    state({ running: true, secs: 0 });

    mount(() => {
        const label = document.querySelector('[data-timer]');
        const timer = setInterval(() => {
            if (!running) return;
            secs += 1;
            label.textContent = secs + 's';
        }, 1000);

        cleanup(() => {
            clearInterval(timer);
        });
    });
</script>
<p>Elapsed: <strong data-timer>0s</strong></p>
<button ly-on:click=":running = !running" ly-text=":running ? 'Pause' : 'Resume'"></button>

cleanup — per-mount resources

cleanup(() => {...}) is registered inside mount() to dispose of specific resources created during that mount cycle — timers, event listeners, subscriptions.

destroy — scope teardown

destroy(() => {...}) is a top-level hook that runs when the container element and its scope are unmounted and destroyed. It complements cleanup() for logic that isn't tied to a mount cycle.

Lifecycle summary: init → scope created → mount → attached to DOM → cleanup (inside mount) → destroy on unmount.

Container scope inheritance

Child containers inherit state and derived values from their ancestors via prototypal scope delegation. A child can read parent state directly, and override it locally.

<div>
    <script type="lyap">
        state({ theme: 'light', user: 'Guest' });
    </script>

    <p>Theme: <span ly-text="theme"></span></p>

    <div>
        <script type="lyap">
            state({ theme: 'dark' });   <!-- overrides locally -->
        </script>
        <p>Child theme: <span ly-text="theme"></span></p>
        <p>User inherited: <span ly-text="user"></span></p>
    </div>
</div>

Scope delegation forms a chain, from the deepest child up to the root:

child scope
  ↓ (inherits from)
parent scope
  ↓ (inherits from)
root scope

Own what you declare. Lyap never owns DOM you didn't opt in to. Only elements carrying ly- directives and lyap scripts belong to a scope — everything else stays untouched.

The Lyap philosophy

  • Structural over convenience — HTML structure and explicit scope boundaries dictate behavior.
  • Concise and effective syntax — short, explicit syntax beats ambiguous magic.
  • Non-invasive DOM ownership — we own only what's declared via ly- directives.
  • 100% CSP compliant & safe — no eval(), no new Function().
